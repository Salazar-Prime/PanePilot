PanePilot organizes work from broadest to narrowest:

```text
Connection
└── Project
    ├── Terminal session
    ├── Actions
    ├── Quick Codex chats
    ├── Files
    ├── Local or remote LLM chat archives
    └── Activity
```

A **connection** identifies where work runs. A **project** gives a stable identity to a
folder on that connection. A **terminal session** is one shell or coding agent in the
project. **Actions** are editable commands with one retained run. Project-scoped Quick
Codex chats stay outside ordinary terminal navigation. LaTeX projects add Manuscript, PDF
Preview, proof comments, and scoped writing chats. Files, provider-archive search, and
activity provide context around those capabilities.

## The application shell

- The top bar shows the current project type and identity, repository state, pinned
  actions, and a secondary-action overflow menu.
- The sidebar groups projects by connection and lists live terminals beneath each
  project.
- The main workspace switches between type-specific capabilities.
- The status bar centers the focused project's tools and shows cross-project Working,
  Responses ready, Needs input, and Blocked counts.

Right-click connection, project, and terminal rows to reveal actions that belong to
that object. Common actions are also available beside the selected project or terminal.

## What PanePilot does not own

PanePilot stores its project metadata, activity, saved terminal output, and saved port
forward definitions. It does not take ownership of:

- Your project files outside explicit saves from the Files tab.
- Codex or Claude provider archives.
- Arbitrary tmux sessions that were not created as PanePilot terminals.
- SSH credentials or agent configuration.

Deleting a PanePilot terminal therefore does not delete the corresponding Codex or
Claude conversation archive.
