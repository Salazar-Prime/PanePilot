## Source layout

```text
src/
├── main/                 trusted Electron services
├── preload/index.ts      typed IPC bridge
├── renderer/src/         React application
└── shared/types.ts       cross-process contracts

scripts/                  native dependency preparation
tests/                    focused Vitest suites
docs/                     Fumadocs documentation application
```

## Working principle

Classify a change before implementing it:

1. Is it base project identity or lifecycle?
2. Is it owned by one project type?
3. Is it a reusable capability such as Files, Repository, Terminal, or Agent history?
4. Does it cross the Electron trust boundary?

That classification determines where state lives, which registry owns behavior, and
which contracts and tests must move together.
