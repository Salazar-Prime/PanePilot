PanePilot intentionally combines a desktop renderer with powerful local and remote
operations. Its safety model depends on keeping those operations narrow, validated, and
visible.

## Renderer trust boundary

- Node integration is disabled.
- Context isolation is enabled.
- The renderer receives only the typed preload API.
- Main-process handlers resolve IDs and validate the referenced objects again.

The Electron renderer sandbox is currently disabled, so a renderer compromise would
still make the preload surface security-critical. Do not expose raw `ipcRenderer`,
arbitrary command execution, unrestricted filesystem paths, or generic shell helpers.

## Filesystem containment

Local and remote file services canonicalize both project root and requested path.
Requests are rejected unless the final real path is the root itself or a descendant.

This protects against:

- `..` traversal.
- Absolute-path escape.
- Symlinks that resolve outside the project.

Writes are limited to existing regular files no larger than 1 MB. The 1 MB limit is
checked in both renderer behavior and trusted services; the service-side check is the
actual security boundary.

## Interactive HTML preview

HTML files open in sanitized, script-free **Static** preview by default. A user must
explicitly choose **Interactive** before project JavaScript can run. Interactive mode
uses a temporary capability URL in an opaque-origin iframe with `allow-scripts`, but
without `allow-same-origin`, Node, the preload bridge, or PanePilot APIs.

The capability provides read-only access to bounded, supported files beneath the
canonical local or SSH project root. It limits cache size, transferred bytes,
concurrent reads, request count, and simultaneous previews. It rejects hidden paths,
unsupported file types, traversal, and symlink escape. Workers, subframes, forms,
popups, downloads, top navigation, and ordinary external web assets are blocked. The
capability is revoked when its preview changes mode, reloads, changes draft or path,
unmounts, crashes, or closes.

This is browser isolation, not an operating-system network jail. Interactive preview
must be used only for trusted HTML because not every browser networking primitive is
guaranteed to be air-gapped. Fonts, media, workers, and libraries that require `eval`
are unsupported.

## Application updates

Packaged macOS builds use Sparkle with a fixed, packaged HTTPS feed and public
verification key. Only the main app frame may request a check, inspect status, or
request restart; renderer input cannot supply feeds, keys, archives, or commands.
Both the appcast and update archive require Ed25519 signatures, with verification
before extraction. The private signing key stays in the maintainer's Keychain.

Checks are manual, system-profile reporting is disabled, and installation requires
an explicit restart action. Ordinary Quit does not authorize a pending update.
Restart checks protect drafts, transfers, inline edits, and non-persistent terminals.
This signing mechanism does not provide Apple Developer ID identity or notarization.
See [Sparkle updates](../development/sparkle-updates) for release and privacy details.

## Remote execution

SSH host configuration remains in OpenSSH. PanePilot uses aliases instead of accepting
arbitrary host flags from the renderer.

Dynamic remote values are shell-quoted before insertion into command strings. Remote
file operations encode a fixed Python script and send variable payloads as JSON over
stdin. Non-interactive actions use timeouts and `BatchMode=yes`.

Remote conversation scanning also executes a fixed Python script. It filters by project
working directory before transfer, emits normalized message data instead of raw archive
files, enforces time and output limits, and keeps its cache in memory.

## Tmux discovery metadata

Tmux user options are editable by any process running as the same remote Unix user.
PanePilot therefore treats `@panepilot_*` values as bounded discovery metadata, not as
authentication or authorization.

Imported UUIDs, profiles, session kinds, timestamps, names, encoded paths, bounded
Action definitions, provider IDs, and LaTeX scope fields are length- and
shape-validated before SQLite writes. A project is matched only on the SSH connection
being scanned and an exact normalized remote folder.
Metadata can preserve an `unsafe` indicator for a running agent, but it cannot bypass
the fresh confirmation required before PanePilot launches a dangerous resume.

Live Action metadata contains the bounded command definition needed for cross-laptop
reconciliation. It is visible to the same remote Unix user, as is the running process
command line, and must not be used as a secret store.

## Port forwards

Every forward:

- Binds only to `127.0.0.1`.
- Uses `ExitOnForwardFailure=yes`.
- Clears inherited forwarding configuration.
- Uses keepalives.
- Stops when PanePilot exits.

Forward target host input permits only hostname and IPv4-style characters without
spaces. Ports must be integers from 1 through 65,535.

## External URLs and native actions

Repository actions accept only `http` or `https` URLs before delegating to Electron's
external browser. Opening a project folder is limited to local projects and uses the
stored folder rather than a renderer-supplied arbitrary path.

## Dangerous agent mode

Permission bypass is:

- Preselected in new Codex, Claude Code, and LaTeX writing-chat launchers, with a
  visible control that can be unchecked before launch.
- Chosen for one agent terminal at a time.
- Persistently marked as `unsafe`.
- Recorded in activity.

Login shells never receive a bypass flag. The setting must never become a silent
application-wide preference.

## Destructive operations

Permanent terminal deletion:

- Stops the exact live backend when necessary.
- Requires UI confirmation.
- Removes PanePilot's saved output and linked events.
- Does not touch provider archives.

The stored Codex provider ID is immutable after linking. This prevents an existing
terminal from being silently redirected to a different provider conversation.

Project archiving stops all exact live terminal and capability backends before changing
state. An archived project can be removed from PanePilot after confirmation without
deleting its folder, `.panepilot` metadata, or provider archives.

## Sensitive data

Saved terminal output and provider chat archives can contain secrets. The SQLite
database is local application data but is not encrypted by PanePilot. Documentation,
logs, error messages, and future telemetry must not copy terminal output or conversation
content by default.
