What changed and what was protected

  • Models count live pane owners; dirty drafts remain pinned while up to 32 clean unowned models / 16 MiB of accounted text are retained. An externally refreshed clean model cannot revert newer disk content or overwrite another live pane. Actual Monaco tests visit 124 clean paths and retain undo, cursor/selection, vertical/horizontal scroll and an early dirty source.
  • Notes drafts restore consistently in Source and Preview. Files can evict inactive clean image bytes while retaining tabs, navigation and drafts. Live/dirty models, active images, text snapshots and Monaco internal/undo memory remain outside the clean budgets.
  • PDF.js validates snapshots before cache acceptance. Rejected PDFs cannot poison future opens; split panes lease independent versions for printing. Page-relative anchors and bounded geometry metadata preserve reading position across zoom, varied-size pages, recompilation and remounts.
  • Terminal output follows one ordered queue and per-surface replay acknowledgement. A slow xterm or headless parser applies backpressure, and disposal/navigation/crash releases its credits. Late-joining panes start their own output sequence. Async launch/attach/stop/delete operations serialize and fence shutdown; inline runner creation and dispatch cannot race between panes.
  • One retry clock and snapshot serve all pending sessions on an SSH connection. Failed transport reads keep terminals retryable; only a successful exact-session observation can complete a missing backend.
  • Notes/Actions/comment IO is asynchronous and mutations serialize by canonical project location within the app. Separate clients/processes and alternative SSH aliases remain a conflict-coordination limitation. Optional Git/diff reads coalesce, sleep while hidden and refresh on foreground return; required lifecycle discovery remains active.

Validation and release preparation

The final full suite passed 117 files / 677 tests, with one file / two optional tests skipped. Application build/typecheck and documentation typecheck/production build pass. Focused tests cover previously reproduced stale-model overwrite, split-owner close, launch-after-shutdown, duplicate inline runners, late output subscriptions, invalid PDF acceptance and quit during a pending load.

The workflow harness loads the actual built application main, preload and renderer with temporary SQLite/projects, a private tmux socket, synthetic archives and fake SSH/rclone. It runs real local PTY/Action output, worker search, Markdown images, unsaved Files/LaTeX drafts and PDF.js rendering. Monaco input is injected through its actual edit API; native keyboard/IME, real SSH authentication, provider execution, compilation toolchains and native printing are outside that harness. Component tests separately verify exact print payloads and compilation/recompile behavior.

Packaged validation executes the worker from inside app.asar, exercises packaged PTY/headless xterm/Sparkle loading, and loads archived Monaco/PDF workers with no renderer errors or network attempts. A separate native updater fixture uses an ephemeral key and temporary apps to test feed/archive rejection, explicit restart and relaunch. The candidate ZIP signature, bundle identity/version/public updater configuration, signed feed, archive signatures and DMG checksum are verified. The original release ASAR is unchanged. Signing is ad-hoc; Apple notarization was not requested.

Prepared local assets and hashes are listed in release-candidate.json. Keep signed notes/XML unchanged. Publication, tags, public feed changes and installation remain separate actions. The integration target is main; source and recovery details are in REPRODUCE.txt.
