F01 · P1

Remote Actions poll and transfer full scrollback while running

Code-confirmed. Action completion schedules another read 250 ms after settlement. The remote path captures the complete tmux history with capture-pane -S - before interpreting exit status; the local path waits until completion. No real SSH throughput was benchmarked.

Each running remote Action can approach four SSH subprocesses and repeated history transfers per second (actual period: 250 ms plus request duration). A capture exceeding the 1 MiB output bound becomes a failed read; even a completed Action can continue polling without being finalized.

Change: Read small lifecycle metadata while running. Capture bounded final output only after completion, independently of the completion decision. Coalesce reads by connection and use an adaptive cadence.

Acceptance: A running action with unchanged output transfers status only; a completed action with oversized history still completes and exposes explicit truncation. Keep exact-session cleanup and interactive input.

F02 · P1

Codex replay retention does large copies for tiny appends

Measured with the production retainTerminalOutput method, constructor bypassed. The 512 KiB buffer coalesces over 256 chunks into a large string; subsequent small appends repeatedly encode, slice, decode and recount that large head chunk.

The retained-size limit bounds stored content but not allocation/CPU work. The benchmark below isolates replay retention; it excludes PTY, headless parsing, IPC and renderer costs.

Change: Extract a byte-counted deque/ring with a head offset. Compact amortized, avoid Array.shift and full-buffer conversions on each small append, and preserve UTF-8 boundaries.

Acceptance: Compare CPU and elapsed time at identical workloads; verify exact suffix, split multibyte text, escape sequences, large writes, reset and shutdown behavior. Do not persist Codex replay to SQLite.

F03 · P1

Interactive SSH operations still block the main event loop

Measured: actual synchronous folder browsing versus asynchronous file browsing with a fake SSH executable sleeping 200 ms. Synchronous Notes/Actions metadata, connection tests and several capability-launch/rename/stop paths also remain in production.

A slow SSH operation can freeze unrelated windows, input and terminal IPC until the child returns. Relevant timeouts range from 3 to 15 seconds; sequential archive/rename checks can compound delays. An async function wrapping spawnSync does not yield.

Change: Introduce one asynchronous command runner with timeout, cancellation, byte bounds and exit handling. Migrate folder browsing and Notes first, then capability launches/stops with explicit mutation serialization.

Acceptance: Use delayed fake child processes to assert timers and unrelated IPC stay responsive. Preserve exact-session ownership checks and archive-only-after-every-stop-succeeds behavior.

F04 · P1

Conversation browsing scans every local archive synchronously

Measured using custom temporary archive roots. list/get recursively traverse and stat all files; changed files are read and parsed in full. The cache retains full transcripts for unrelated projects without a byte bound. Selected-chat get also depends on every raw search keystroke, despite list debounce.

Cold cost scales with all archive bytes, warm cost with all archive files, and search with queried text. Main-thread stalls and retained transcript memory grow independently of the number of visible conversations.

Change: Build an asynchronous or worker-owned file catalog with identity/revision/parser version, incremental append parsing with rewrite fallback, lazy details and a byte-bounded cache. Reuse it for thread/subagent discovery. Use a rebuildable FTS index if volume warrants; avoid refetching a transcript solely for search metadata.

Acceptance: Benchmark cold/warm/mutated-file cases at 100, 1,000 and larger collections. Preserve read-only archives, complete search and explicit cross-folder descendants.

F05 · P1

Concurrent shared-comment edits can lose a successful write

Reproduced with real ProjectMetadataService file IO in a temporary local project: two concurrent create calls both succeeded, but only one comment remained. Both read the old list before replacing the file. This is a service-level probe, not a claim about a particular UI gesture.

Atomic replacement prevents partial JSON but not lost updates. A client-local queue alone also cannot protect two laptops editing the same shared project. Shared Action read/replace operations have an analogous untested cross-client risk.

Change: Provide a canonical-location-scoped metadata mutation API. Serialize within one client and add host-side revision checking or a locked merge for separate clients; retain authoritative .panepilot files.

Acceptance: Concurrent creates retain both IDs; create/delete cannot resurrect entries; stale revisions report conflicts; migration cannot overwrite a newer file. Preserve symlink and path guards.

Markdown image loading has no aggregate admission budget

F07 · P1

PDF snapshots retain unbounded renderer-lifetime memory

Measured: visit/unmount eight distinct 2 MiB mock PDF snapshots; cache strings and external backing storage retain 22,369,632 bytes after GC, with zero PDF page nodes mounted. pdfSnapshotCache has no eviction; destroying the PDF.js proxy does not remove its snapshot.

A 32 MiB per-PDF cap does not bound all projects. Base64 expands bytes by about one third, before active PDF.js, worker, native or GPU memory. Those additional costs were not measured.

Change: Introduce owned immutable snapshots with byte accounting and bounded hot memory, possibly binary transport and cold temporary-file storage. Keep lightweight page/zoom/scroll state separately.

Acceptance: Never silently reread a changed disk PDF after eviction: preserve the exact displayed and printed snapshot until explicit manual/auto compile. Test project changes, cleanup, failure and split-pane ownership.

F08 · P1

Editor-model ownership and dirty-cache eviction need repair

Code-observed. LaTeX uses keepCurrentModel and unique project/path URIs but does not dispose text models. The 32-entry source cache does not own Monaco model lifetime and can evict dirty snapshots and clear restart guards. Files/Notes path switches also leave old models outside tab-close disposal.

Model text/undo history can accumulate. Separately, revisiting a dirty source after snapshot eviction may load disk content over its retained model. That dirty-eviction scenario needs a dedicated runtime regression; it was not reproduced here.

Change: Create a model registry with split-pane reference counts, dirty-state pinning and bounded clean-model retention. Separate drafts from disposable content. Dispose only models with no editor/draft owner.

Acceptance: Open over 32 sources, keep early dirty drafts, remount and verify exact text/undo. Closing clean tabs must release models; one pane must not dispose another pane’s model.

F10 · P2

The intended four-surface terminal limit can be exceeded

Code-path analysis, not a mounted-surface benchmark. Inactive cached projects receive selectedSessionId=null, choose their first open tab and append it even when absent from the four retained entries. Four projects retaining a non-first tab can therefore render seven surfaces in one pane.

Unbudgeted xterms attach and consume output. The helper cache length alone cannot establish the number of mounted terminals.

Change: Only append an uncached activeSession when that workspace is active. Inactive projects must render exactly their retained entries.

Acceptance: Render four projects with multiple tabs, visit a non-first tab in each and count actual xterm/attach subscriptions. Keep hidden input/resize guards and preserve backend sessions on disposal.

F11 · P2

Optional UI polling lacks a consistent visibility/settlement policy

Code-observed: Git polls every 12 s; selected-connection discovery every 15 s; running LaTeX edit diffs every 1.8 s; enabled PDF auto-compile checks every 2.5 s. Git/diff paths lack in-flight guards; these effects lack explicit document-hidden gates. Chromium may throttle timers, so the listed rates are nominal, not measured hidden-window rates.

LaTeX diff reads and compares all bounded source files even behind another capability. Slow requests can overlap. Git status invokes three git/SSH commands, including stable root/origin metadata, per refresh. Existing discovery single-flight already prevents some duplicate work.

Change: Use settlement-based scheduling, per-key single-flight, cancellation/identity fences and explicit foreground/background policies. Cache root/origin separately and batch remote Git reads. Keep required agent lifecycle monitoring; establish intended background auto-compile behavior before changing it.

Acceptance: Count requests while visible, hidden, switched and slow. No overlap; returning to foreground refreshes promptly; real running jobs remain running.

F12 · P2

Offline recovery duplicates full host scans per session

Code-confirmed. Ordinary discovery coalesces by connection; runRemoteReconnect instead calls listRemoteTmuxSessions independently for every disconnected session. Wake forces many sessions to reconnect together.

N sessions on one unreachable host can perform N equivalent scans per backoff round, plus ordinary discovery. Backoff reaches about 30 s plus command duration but does not consolidate host work.

Change: Own scan/backoff state by connection, distribute one result to exact-session consumers, and add bounded concurrency/jitter.

Acceptance: With many sessions on one offline host, assert one scan per round. Unreachable transport must never be interpreted as a successfully observed missing terminal.

F13 · P2

Headless parsing and output queues are not demand-bounded

Code-observed. Every attached runtime creates headless xterm with 1,000 scrollback rows and parses each chunk, including tmux shell/Action profiles without screen detectors. Every chunk is sent to the renderer without an app-level acknowledgment/backpressure protocol.

Renderer surface eviction does not stop main-process parsing. The 512 KiB replay cap does not bound parser/IPC queues. The installed headless xterm WriteBuffer eventually rejects extremely large pending data; no normal-use queue overflow was benchmarked.

Change: Omit unnecessary headless screens for tmux non-agent profiles, retain plain-PTY preview and agent detection screens, and add byte-budgeted parser/IPC flow control with subscriber-aware batching.

Acceptance: Stress high-output sessions and slow consumers while monitoring queued bytes and CPU. Preserve raw byte ordering, escape sequences, sticky lifecycle states and useful background monitoring.

F21 · P3

Small durable-output transactions still amplify writes

Measured with saturated shell output and autocheckpoint disabled: compare 512 B, 4 KiB and 16 KiB appends at identical 1 MiB total input. This measures cumulative logical WAL bytes; production already batches for 250 ms and uses chunked storage.

Testing gaps and safeguards

An AST inspection found 24 of 98 TypeScript test files contain 52 explicit application-source reads. Some tests assert strings, function names or even a comment rather than behavior. This is not a coverage percentage: many of those files also have meaningful tests. Such checks can reject harmless extraction while missing the lost-update and terminal-surface issues.

Before moving these boundaries, replace behavioral source-string claims with delayed IPC, controlled clocks, rendered transitions and assertions on side effects. Existing isolated Electron scripts are a good foundation; add a discoverable desktop UI test command. Keep actual policy checks where they express an architectural requirement.

Preserve: targeted project updates; output-free renderer/runtime hydration; UTF-8-safe bounded replay; no durable Codex output; provider archives read-only; explicit per-session unsafe mode; transport state separate from agent lifecycle; exact tmux/thread identity; hidden ordinary input/resize guards; canceled/stale-load fencing; subagent settlement/visibility checks; HTML resource budgets; PDF render cancellation and offscreen canvas shrinking.
