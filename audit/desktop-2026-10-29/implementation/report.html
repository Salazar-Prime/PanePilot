Behavior and refactoring

  • TerminalOutputBuffer owns the replay tail in bounded segments, replacing repeated whole-buffer copies. Focused tests cover Unicode boundaries, ANSI/NUL bytes, oversized writes and 500,000 tiny appends.
  • TerminalManager now polls Action status before capturing output. Final capture is bounded on the host and cannot prevent a known completion. Concurrent reconnect and discovery scans share their pending result per connection; later calls read fresh state.
  • Markdown image admission separates resource ownership from rendering. The three-read gate spans previews and render generations. Each document admits at most 16 unique project paths and 16 MiB of accepted data-URL text, counting repeated DOM images. Queued reads cancel immediately; active IPC holds its slot until it settles. Transient responses/browser decoding can require extra memory. External HTTPS images retain their existing behavior.
  • Inactive project workspaces no longer create extra fallback xterms. The actual-component test observes 1 → 2 → 3 → 4 surfaces, eviction on the fifth project, warm reuse and no backend stop. Hidden writing chats preserve draft and session while suppressing input, resize and composer submission.
  • Canonical-location comment transactions include migration and the entire read/modify/write sequence. Independent projects remain concurrent and a failed transaction releases the queue. This queue does not protect separate clients or alternate SSH aliases.
  • SSH folder browsing, canonical path checks, project creation validation and connection tests yield the main loop. Canonical verification no longer enumerates a whole directory. Five Google Drive reads now request project runtime state without loading saved terminal output.

Validation and limits

The full suite passed 103 files and 572 tests, with one file/two tests skipped. It ran before the final Markdown shared-gate refinement; that final refinement passed its focused unit/component tests and the subsequent complete build/typecheck. Benchmark TypeScript and whitespace checks also pass. Independent code review found no fix-worthy regressions.

Packaged checks load headless xterm, run one exact synthetic PTY command, and load Sparkle’s native bridge without initializing update checks. The archived renderer smoke uses a disposable profile and synthetic IPC: terminal output, Files/LaTeX Monaco, all six editor/PDF worker types and real PDF.js canvas rendering pass with no renderer errors, failed assets or attempted network requests. The production application main process and live profile were not launched. These checks do not replace a later real-workspace or signed-release acceptance test.

Next refactoring stages

  1. Give Monaco models, dirty drafts and immutable PDF snapshots explicit owners and byte accounting. Protect split-pane references and exact snapshot printing before introducing eviction.
  2. Move provider archive discovery/parsing into a shared asynchronous catalog with bounded transcript details; reuse it for history and subagent presence.
  3. Extract asynchronous tmux transport and connection recovery from TerminalManager. Add settlement-based scheduling, connection-level backoff and output flow control while preserving exact-session identity.
  4. Separate Store domain queries and ordered migrations; verify exact legacy bytes before removing duplicate storage. Add history pagination without silently deleting durable user history.
