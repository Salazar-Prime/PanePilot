PROVENANCE

Both variants use exactly the same final production out/ bundle: all 101 files
were compared byte-for-byte. This bundle corresponds to production source commit
dfc14ec. It includes the other desktop efficiency fixes in that commit.

The before variant restores package.json, package-lock.json, and
electron-builder.yml from the pre-implementation audit revision 538f5dc. The
after variant uses dfc14ec. Both use Electron 39.8.10, electron-builder 26.15.3,
arm64, npmRebuild=false, mac.identity=null, and publish=never. Both use the same
real installed node_modules tree and cached native modules/framework.

Only the before variant's dependency classification and renderer-license resource
configuration differ. No build hook or dependency install ran during the offline
package-lock update. All 629 resolved dependency versions, integrity hashes, and
dependency graphs were unchanged; 54 entries changed development classification.

An initial experiment using a symlinked node_modules root in temporary staging
directories produced dependency-collector warnings. Those artifacts were rejected
and are not represented in any saved comparison. The validated pair was built
against the actual checkout dependency tree. Original package files were saved
and restored in a finally block; restoration and dependency graph equality were
checked after packaging.

The validated builds report duplicate dependency references, which the builder
deduplicates, and an existing recommendation about @electron/rebuild. They do not
report missing dependency paths. The preserved release/mac-arm64/PanePilot.app
ASAR still has its original SHA-256:
bd9cfbec7a9733ca93c5bbdba6eee6ffcd2a321965e466d025acc9168532dbf8

REPRODUCTION

Use Node >=20.19.0 (validation used Node 22.13.0). The existing benchmark helper
inspects an explicit app path without modifying or launching the app:

  node scripts/benchmark-desktop-package.mjs /path/to/before/PanePilot.app --output /tmp/package-before.json
  node scripts/benchmark-desktop-package.mjs /path/to/after/PanePilot.app --output /tmp/package-after.json

Run the native dependency smoke in the packaged executable's Node mode:

  ELECTRON_RUN_AS_NODE=1 /path/to/after/PanePilot.app/Contents/MacOS/PanePilot scripts/test-packaged-runtime.cjs /path/to/after/PanePilot.app

Run the renderer smoke with the required explicit archived index path:

  node scripts/test-packaged-renderer.mjs /path/to/after/PanePilot.app/Contents/Resources/app.asar/out/renderer/index.html /tmp/packaged-renderer-smoke.json

For a fresh same-source pair, use a disposable checkout of dfc14ec, install its
locked dependencies, and run npm run build once. Save its package and lock files;
for the before build use the three packaging files from 538f5dc, without rerunning
the renderer build or installing different dependency versions. For each build,
load its electron-builder YAML into a temporary config, override only output to
a distinct temporary directory and mac.identity to null, then run:

  node node_modules/electron-builder/cli.js --mac --dir --arm64 --publish never --config /path/to/temporary-config.yml

Restore the after package and lock in a finally block before the second build.
Use a real dependency directory; a symlinked node_modules root is not equivalent
for electron-builder's collector. Keep the normal release/ directory untouched.
Compare logical regular-file sizes, ASAR contents, runtime dependency resolution,
worker loading, and licenses. Allocated bytes alone can vary for identical files.
